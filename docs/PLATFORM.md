# Platform invariants — what keeps shipped files working

The properties a file must keep so that shipped decks — including ones saved
years ago — continue to open, save and be re-hosted. **Breaking an invariant
here doesn't break the build; it bricks files that are already on disk.**

`slides/` is the only app. When this doc and the code disagree, the code that
*shipped* wins — fix the doc.

## 1. One file is the product

A deck is a single self-contained HTML file carrying the document data, the
viewer and the editor. It must work from `file://`, from a static host and
from an email attachment — no backend, no CDN, no network required to open,
edit, present or save. The poll service is the one network dependency, and
only for poll elements while presenting.

Byte order of a shipped shell (`scripts/postbuild-compress.mjs`):
`chrome → NOTICE → tooling comment → plaintext #tessera-doc → splash → compressed payloads`.
Runtime JS/CSS ship deflated in `tessera/deflate-b64` script blocks with a ~1KB
loader (DecompressionStream → blob import).

## 2. The splice contract (FROZEN)

Self-save and re-hosting (`scripts/upgrade-deck.mjs`) work by re-splicing the
document block into a shell, and old shells' updaters are frozen code. Every
build must keep:

- a `<script type="application/tessera+json" id="tessera-doc">` block that is
  **plaintext** (never inside the compressed payloads), same id, forever;
- block content that is JSON with `<` escaped as `<` — it can never
  contain `</script>`;
- the SAME escaping on every other plaintext data block the shell carries
  (`application/tessera+*`, written by `registerShellBlocks` — language packs
  already embedded in older files);
- a file that survives `DOMParser → splice → outerHTML` round-trips, with
  balanced script tags and a v0.1.0-style *text* splice still producing a
  well-formed document.

`node scripts/shell-gate.mjs <shell.html>` checks all of this on a built shell.

Files saved before the rename carry older names for the block id and type,
the `format` value and the encrypted envelope. Every reader accepts both
(the old names live only in `kernel/src/legacy.ts` and `slides/src/legacy.ts`);
writers write the names above, except that an existing document keeps the
`format` value it was written with (an older shell refuses any other).

## 3. Document identity & format

- `format: "tessera/slides"` with an integer `version`.
- **Formats are additive.** Every version opens files from every earlier
  version; unknown fields (legacy `collab` included) are preserved, not
  stripped. There is no server to migrate old files.
- `docId` (uuid) is minted once at creation/load and never regenerated by a
  tool. It keys autosave recovery and tab-to-tab sync. "Save a copy…", the
  identity banner's "Make this file independent" and `slide.py fork` are the only
  sanctioned ways an id changes.
- Locale/language never enters the document format; i18n follows the viewer.

## 4. Save, autosave, encryption

- Self-save: capture the pristine shell at boot, swap the `#tessera-doc` block,
  re-serialize (since 2026-10-22 from a template split once, byte-identical to
  the clone-and-outerHTML path). File System Access API first, the local
  bridge's `/save` next, download fallback.
- The bridge (`scripts/agent-bridge.py`) is NOT frozen code but it serves
  frozen shells: it keeps accepting every `/save`, `/tick` and `/claim` form a
  shipped shell sends — the JSON `/save {file, docId, html}` without a base, a
  `/tick` with only a `pending` count — alongside the current raw-body `/save`
  with a base version (`docs/agent-live.md`, "Saving").
- Autosave (IndexedDB) keeps a latest-recovery snapshot + a capped version
  timeline, keyed by `docId`. Read-only players skip autosave.
- Password-protected docs use the `tessera/enc` envelope (PBKDF2-SHA-256 300k →
  AES-GCM-256 over the doc JSON) *inside* the plaintext block. The editor no
  longer sets passwords, but such files still open behind a password gate and
  **every write-back path stays encrypted** while the password is held in
  memory; they are never snapshotted to IndexedDB in plaintext.

## 5. Tab-to-tab sync

Two tabs or files with one `docId`, open in the same browser profile, merge
their edits over BroadcastChannel through the in-house CRDT
(`slides/src/sync/`, `docs/collab-design.md`). Nothing leaves the machine.

- Engine changes (`sync/crdt.ts`) require the convergence rig
  (`node scripts/test-sync.ts`) before merge. No exceptions.
- Files saved by older shells may carry `doc.collab` relay credentials; keep
  the field, never connect with it.

## 6. Kernel vs app

**`kernel/src/`** holds what has no slide shape (evolve carefully, one change
at a time): `save.ts` (splice + `tessera/enc`), `autosave.ts`, `anim.ts`,
`charts.ts`, the `i18n.ts` engine, `app.ts` (`configureApp`), `doc.ts` (the
`KernelDoc` envelope). The app imports these through facades at its own
paths. Everything else — the model, renderer, editor, sync, polls — is the
app's.

## 7. AI round-trip

The **document JSON** is the interchange unit for agents. The shell's tooling
comment points them at `#tessera-doc`; a running file exposes `window.tessera`
(`doc`, `serialize()`, `loadDoc(json)`, `requests`, `agent`, …), and the local
bridge (`docs/agent-live.md`) patches an open editor. Keep model JSON pure
data — template strings over functions (chart formatters are `{b}/{c}`
templates, never code).

## 8. i18n

~1KB `t()` with English-string-as-key (missing key = English). Never call
`t()` at module scope (frozen at import). `select()` localizes display labels
only — model values stay English words. Audit with `setLocale('x-pseudo')`.

The catalogs are bundled: the per-locale files under `slides/src/i18n/` are
the authored source, packed key-once into `packed.ts` by
`scripts/build-i18n.mjs`. New UI strings must land in **all** catalogs in the
same change. Nothing is fetched; a pack block already embedded in an older
file still loads, under the §2 escaping, and falls back per string to English.

### Direction (RTL) — two halves, never confuse them

**Content direction belongs to the DOCUMENT and is per element.** Text
resolves its own base direction from what the author typed (`dir="auto"` in
the renderer), so an Arabic paragraph reads RTL beside an English one in the
same file.

**Chrome direction belongs to the VIEWER and never enters the format.** The
editor flips to RTL when the viewer's locale is RTL. `applyDirection()` runs
AFTER `capturePristine()`, so a saved file can never carry a `dir` attribute.
Lay chrome out with logical properties (`inset-inline-start`,
`margin-inline-end`, `text-align: start`) and it mirrors itself.

> **INVARIANT — the document never mirrors.** Elements carry absolute x/y
> model coordinates, so a document MUST render identically regardless of who
> opens it. Every surface that renders document content is pinned
> `direction: ltr`: the document root, thumbnails, the scroller, the present
> overlay, and any body-mounted overlay that reads coordinates (e.g.
> Moveable's control box). A new document-rendering surface MUST pin it; the
> pin also keeps direction away from `scrollLeft`.
